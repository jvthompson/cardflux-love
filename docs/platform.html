Platform Integration src/platform

Why a platform layer

LÖVE's own API deliberately knows nothing about HTTPS, native dialogs, process launching, or vendor SDKs like Discord's. Everything under src/platform/ exists to bridge that gap using LuaJIT's ffi module to call straight into Win32, WinHTTP, the MSVC runtime, and (for Discord) a vendored native DLL. All of it is Windows-specific and all of it is best-effort: a missing DLL, an unsupported OS, or an FFI failure should degrade a feature gracefully rather than crash the app, so most functions here are wrapped in pcall with a quiet fallback. See architecture.html for how src/app.lua wires these modules into the LÖVE callback lifecycle.

window.lua — borderless window chrome

src/platform/window.lua
Frameless window chrome: a custom title bar that still drags/snaps/double-click-maximizes like a native one, resizing from the edges, and DPI scale detection — all via SDL's window hit-test callback.

Cardflux draws its own title bar (see App.draw's drawTitleBar in architecture.html) instead of using the OS frame, so Windows has no native hit-testing to tell it "this pixel is the title bar, drag the window" or "this pixel is the edge, resize it." SDL exposes exactly that as a hit-test callback (SDL_SetWindowHitTest), and this module installs one.

W.install()

Loads SDL2 via FFI, sets SDL_MOUSE_FOCUS_CLICKTHROUGH (so the click that refocuses the window from outside also registers as a real click — by default SDL swallows it, requiring an annoying second click), force-enables window resizing (LÖVE creates borderless windows non-resizable even when conf.lua asks for resizable, which also silently blocks maximizing on Windows), and installs the hit-test callback.

hitTest(window, point) (local, the installed callback)

Given a point in physical pixels, returns one of SDL's HT.* constants: a resize edge/corner when not maximized and not using the native frame, HT.DRAGGABLE when inside the title bar height and the registered dragArea function says so, else HT.NORMAL. Runs inside SDL's event pump — see the note on JIT in main.lua's custom love.run, which keeps its polling loop out of the JIT specifically because this FFI callback can't be entered from a JIT-compiled trace.

W.setDragArea(fn)

Registers fn(x, y) -> bool, called by hitTest to ask whether a given logical-pixel point in the title bar is empty (draggable) space rather than one of the title bar's own buttons. src/app.lua calls this once with a closure over the back/close/maximize/theme button rects it just drew.

W.dpiScale()

Reads the display DPI of the monitor the window is currently on via SDL_GetDisplayDPI, cached for half a second at a time. Relies on conf.lua having made the process per-monitor DPI-aware on Windows (SetProcessDpiAwarenessContext); without that the window gets 96-DPI logical pixels that Windows then stretches, and this would just report 1.

W.desktopSize() / W.setMinimumSize(w, h) / W.setScale(s)

Used by src/app.lua's applyScale to compute and enforce a window size that stays usable (at least the logical 960×600 minimum) on the current monitor at the current DPI × UI-scale-setting product.

W.toggleMaximize() / W.toggleFrame()

toggleFrame is bound to F11: swaps between the borderless custom chrome and the native OS frame by flipping love.window.setMode's borderless flag, then re-installs the hit-test (a non-resizable window — which setMode can reset to — ignores maximize).

winproc.lua — hidden process launches

src/platform/winproc.lua
Runs a command line with no visible console window, via CreateProcessW + CREATE_NO_WINDOW.

Lua's io.popen/os.execute would flash a terminal window open and shut in a fused GUI build — jarring for something like a background update check. winproc.lua exists purely to avoid that, and is the primitive update_worker.lua uses to run tar.exe (extracting the update zip) and powershell.exe (launching the update helper and, elsewhere, rotating imported JPEG card art — see image_utils.lua).

W.quoteArg(s)

Quotes one argument for the MSVCRT command-line parser (the same escaping rules every Windows C program's argv splitting expects) — handles embedded quotes and trailing backslashes correctly, which naive '"' .. s .. '"' quoting does not.

W.run(cmdLine, opts)

Starts cmdLine via CreateProcessW with the CREATE_NO_WINDOW flag. With opts.wait, blocks (up to opts.timeoutMs, default forever) via WaitForSingleObject and returns the process's exit code; otherwise returns true once the process has started. Returns nil, message on failure to launch.

W.currentPid()

Wraps GetCurrentProcessId — used to pass this process's PID to the detached update-helper script so it can wait for this process to exit before overwriting its files.

winhttp.lua — HTTPS without LuaSocket

src/platform/winhttp.lua
A minimal blocking HTTPS GET built on the WinHTTP API via FFI.

LÖVE bundles LuaSocket, which has no TLS support, and both the GitHub API and GitHub's release-asset CDN are HTTPS-only — so the self-updater needs its own HTTP client. WinHTTP is a good fit: it's a Windows system component (no extra DLL to ship), handles the TLS handshake itself, and transparently follows the HTTPS→HTTPS redirect GitHub's release assets use to hand off to their CDN. Being blocking, every call into this module happens on a background thread (see update_worker.lua), never the main thread.

H.parseUrl(url)

A small regex split of an https://host[:port]/path URL into its parts; refuses anything not scheme https (this module intentionally doesn't support plaintext HTTP).

H.get(url, opts)

Opens a WinHTTP session/connection/request (WinHttpOpen → WinHttpConnect → WinHttpOpenRequest with the FLAG_SECURE TLS flag), sends it with optional extra headers, and reads the response in 64 KB chunks. Returns status, body, or streams via opts.onChunk(data, received, total) instead of buffering the whole body in memory — the mechanism the update downloader uses to report download progress and to avoid holding a full release zip twice over. Returns nil, message on any failure, with the specific WinHTTP call that failed and GetLastError()'s code named in the message.

The automatic-proxy access type (ACCESS_AUTOMATIC_PROXY, Windows 8.1+) is tried first with a fallback to the unconditional default-proxy type, so the module still works on a system too old to support the newer flag.

file_dialog.lua — file/folder pickers

src/platform/file_dialog.lua
Thin, now-mostly-historical façade over the in-app file picker screen (src/ui/screens/file_picker_dialog.lua).

This module used to show a real native dialog — a Vista-style IFileOpenDialog via COM/FFI on Windows, zenity/kdialog on Unix — but the native Windows dialog had an unfixable z-order bug when the app's borderless window was maximized, and there was never a native implementation for Mac at all. The native dialog code was replaced by an in-app picker UI (commit "Replace the native file/folder dialog with an in-app picker"), and this module now just forwards to it, keeping every caller's require("src.platform.file_dialog") path and call shape stable. It is still the module every screen requires — home.lua, game_picker.lua, deck_library_dialog.lua, gamedef_editor.lua, the gamedef editor's common.lua/sets_tab.lua, and the server screens' admin.lua/login.lua/lobby.lua — so the picker UI itself is a drop-in replacement rather than a separate code path callers had to adopt.

D.isAbsolute(path)

Still implemented natively here (not delegated) since it's a pure string check: Windows drive-letter or UNC prefix, or a leading / elsewhere.

D.openFile(opts, onResult) / D.pickFolder(opts, onResult)

Both now simply call through to src.ui.screens.file_picker_dialog's openFile/pickFolder. Async in both the old and new implementation: onResult(path) fires once with an absolute path, or nil if the user cancelled. opts carries title, filters ({ {name=, extensions={"png",...}} } — see D.imageFilters/D.jsonFilters for the two filter presets every caller reuses) and initialDir.

updater.lua & update_worker.lua — self-updates

src/platform/updater.lua
Ports lib/services/update/{update_checker,app_updater}.dart. Checks GitHub Releases once per launch and, on request, downloads, extracts and installs the latest release, then relaunches.

Only a fused (packaged) Windows build checks or installs updates (U.supported()) — a dev run's "install folder" is the source tree, which isn't something the updater should ever overwrite. The repo, release asset name and executable name it targets come straight from src/version.lua: releaseRepo = "jvthompson/cardflux-love", releaseAssetName = "cardflux-windows.zip", exeName = "Cardflux.exe" — note this is a separate GitHub repo/release stream from the original Flutter app, specifically so the LÖVE port's own build numbers (compared via the +N suffix on a tag like v0.2.0+10) never collide with or get shadowed by Flutter's.

U.check(force)

Spawns a worker thread running update_worker.lua with {op = "check", ...}; on finding a newer release with the expected asset, sets U.state = {available = true, tag, url, size}, which the Home screen's update banner reads. force (from the --update-check CLI flag) bypasses the fused-build-only gate for testing.

U.apply(onProgress, onDone)

Spawns a worker with {op = "apply", url, size, installDir, excludeDirs, exeName}, where installDir is paths.appDir() and excludeDirs is whichever of the game/deck library folders turn out to live inside it (U.pathsInside) — so an update never wipes a user's installed games or decks even if their library folders happen to sit under the install directory. onProgress(phase, fraction) reports "downloading", "extracting", "verifying" or "launchingInstaller"; on success the caller must quit immediately afterward so the detached helper can take over the file replacement.

U.pickRelease(release, localBuild, assetName) / U.buildFromTag(tag)

Pure logic, directly unit-testable (see tests-tools.html): parses the +N build suffix off a tag like v0.1.0+49 and picks a release only if its build number is strictly newer and it carries an asset exactly named assetName.

U.helperScript(o)

Generates the PowerShell source for the detached install helper: waits (up to 30s) for this process to exit via Wait-Process, then robocopy /MIRs the staged, extracted build over the install directory — excluding the library folders — relaunches the executable, and deletes its own staging files and itself. Robocopy's 0-7 exit codes are all "success" bit flags; only ≥8 is treated as failure.

U.update()

Polled every frame from src/app.lua's App.update: drains each spawned job's message channel, forwards messages to the caller's onMessage, and detects a worker thread that died without sending a final done message (reporting thread:getError() as the failure).

src/platform/update_worker.lua
The actual network/disk work for both the check and apply operations, run entirely on a background thread so GitHub round-trips and a multi-megabyte download never stall the UI.
check() (local)

GETs https://api.github.com/repos/<repo>/releases/latest via winhttp.lua, decodes the JSON body, and delegates to U.pickRelease. Reports failure as a plain string so the result stays flat (no nested tables) when pushed over the LÖVE thread channel.

apply() (local)

The full install sequence: download the release zip into a fresh temp folder while streaming progress updates (throttled to once per 100ms); extract it with Windows' bundled tar.exe (via winproc.lua — bsdtar reads zip archives despite the name) rather than any Lua zip library; verify the staged folder actually contains exeName; write out the PowerShell helper script from U.helperScript (with an added UTF-8 BOM so PowerShell reads non-ASCII paths correctly); and finally launch it.

encodePs(script) (local)

Encodes the launcher command as base64 UTF-16LE for powershell.exe -EncodedCommand, sidestepping every layer of command-line quoting that would otherwise apply to a script containing arbitrary paths.

The helper itself is launched through Invoke-CimMethod -ClassName Win32_Process -MethodName Create (WMI) rather than as a direct child process — a comment in the source notes this mirrors a finding from the original Flutter port: a plain child process does not reliably survive this process's exit, but a process created via WMI becomes a child of the WMI host instead and does. The outer powershell.exe call's own exit code is WMI's ReturnValue (0 = success), checked before declaring the update launched.

discord.lua — Rich Presence & invites

src/platform/discord.lua
Ports lib/services/discord/*: Rich Presence plus the friend-invite flow (OAuth, friends list, activity invites, join callback) over Discord's Social SDK (discord_partner_sdk.dll), via a large hand-written FFI binding.

Everything here is decorative — showing what you're playing to friends, letting them one-click join — and must never crash or block a game, so the whole module is designed to degrade to a silent no-op: on any platform/DLL/SDK failure, enabled stays false and every public function either does nothing or calls its callback with a failure result. It only attempts to load at all on 64-bit Windows.

D.init()

Declares the SDK's C ABI (CDEF, a large hand-maintained subset of cdiscord.h), loads discord_partner_sdk.dll from next to the executable, creates and initializes a client with the app's hard-coded Discord application id, registers the launch command and the activity-join callback (live from startup, since this process might be the one being invited into a game), and publishes an initial "In the menus" presence.

D.update(dt)

Called every frame from src/app.lua. Pumps the SDK's callback queue (Discord_RunCallbacks) at a fixed 0.1s interval rather than every frame, dispatches queued events (status changes, join secrets, request completions) to their handlers, and times out any pending request/status-wait past its deadline.

D.publish(details, state, party) / D.setPlaying(gameName, playerCount, maxPlayers, party) / D.setIdle()

Builds and pushes an Activity to the SDK. De-duplicates identical presence updates via a cached key so an unchanged state doesn't re-call the SDK every frame. The hosting-only party table (partyId, currentSize, maxSize, joinSecret) is what makes Discord show a clickable "Join" button to friends — its joinSecret is simply "host:port", parsed back out by D.parseJoinSecret on the receiving end and handed to App.showDiscordJoinPrompt (see architecture.html) via D.onJoinSecret.

D.ensureAuthorizedAndConnected(onDone) / D.fetchInvitableFriends() / D.sendGameInvite(friendUserId, onDone)

The invite flow: tries a saved OAuth refresh token first (settings.keys.discordRefreshToken) to skip the consent screen, falling back to a full PKCE-style Authorize → GetToken round-trip when there's no saved token or it's been revoked. Once connected and ready, fetchInvitableFriends lists real Discord friends (an Invisible friend still reports as Offline, so the list isn't filtered by status) and sendGameInvite pushes an activity invite carrying the host's current presence/party to one of them.

ABI note worth flagging for anyone extending the binding: several SDK callbacks take a Discord_String {ptr,size} struct by value. LuaJIT FFI callbacks cannot receive a struct by value directly, but on the Win64 calling convention any struct whose size isn't 1/2/4/8 bytes is actually passed as a hidden pointer to a caller-allocated copy — so declaring the parameter as Discord_String* in the callback's cdef is ABI-identical and works. Every SDK-calling function is also explicitly marked jit.off, since a native callback that re-enters Lua must not be invoked from a JIT-compiled trace.
