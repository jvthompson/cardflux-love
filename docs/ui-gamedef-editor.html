What a "game definition" is

A game definition (a "gamedef") is the complete description of one playable card game: its name, its card backs, its tag groups (the vocabulary used to classify and filter cards — things like "Rarity" or "Color"), its board zones (piles and widget slots, shared or per-player), its card sets (folders of card art), and every individual card definition. On disk it is a folder containing a gamedef.json file plus one subfolder of images per set. The exact shape of every field below (GameDefinition, ZoneDefinition, CardDefinition, GameSet, TagGroup, CardBackDefinition, PackSetting, ...) is defined in src/core/models.lua; this page covers the editor UI built around that data model, not the model itself.

The editor is reached from Home's corner tools (the build icon) and pushes gamedef_editor.Entry.new(). Loading and saving the JSON file, copying art into the game's folder, and the duplicate-detection logic used by the Tools menu all live in src/data/gamedef_ops.lua, which every file on this page calls into rather than touching the filesystem directly.

The editor keeps its working GameDefinition with bare image file names (e.g. "card.png", not a resolved absolute path) — see gamedef_ops.loadGameDefFile. Anything in the editor that needs to actually draw an image (the Cards tab's preview, a card-back thumbnail, ...) builds a short-lived display copy with the path resolved through src/data/image_resolver.lua; the resolved path is never written back. That is why common.displayCard/common.displayCardBacks exist — every tab uses them rather than resolving paths itself.

gamedef_editor.lua — Entry & Editor

src/ui/screens/gamedef_editor.lua
Ports game_definition_editor_entry_screen.dart and game_definition_editor_screen.dart: pick/create a game, then edit it across four tabs.

Exports { Entry, Editor, newGameDefinition, openExistingGameDefinition }. The module-level M.newGameDefinition(onCreated) and M.openExistingGameDefinition(onOpened) are shared by both screens below (and also by Home's "New"/"Open" affordances via the Entry screen), so "create" and "open" behave identically no matter where they're invoked from.

Entry screen

Entry.new() scans the whole games library folder (src/data/paths.lua's gamesDir()) via ops.scanGameLibrary, deferring the actual scan by two frames (pendingScan) purely so a progress bar is visible first. It then shows every discovered game as a tile grid — reusing GamePicker.drawGrid directly rather than a full GamePicker instance, since Entry needs its own folder-choosing and New/Open buttons around the grid rather than GamePicker's. Clicking a tile opens that game in the Editor (openEditor(folderPath, game)); "New Game Definition..." and "Open Existing..." are full-width buttons below the grid, both just calling the module-level helpers above and then App.push(Editor.new(...)).

Entry:changeRoot() picks a new library folder (through src/platform/file_dialog.lua) and, if the old folder has files, confirms via GamePicker.maybeMoveLibraryFolder before calling paths.setGamesDir and re-scanning. Entry:resume() (called when the editor screen above it on the stack is popped) re-reads paths.gamesDir() and refreshes, so a folder change made elsewhere in the app is picked up when the user returns to this screen.

M.newGameDefinition(onCreated)
A small dialog prompting for a game id. Validates with ops.validateGameId and checks the id isn't already taken under the library root, then calls ops.createGameDefinition(root, id) to write a stub gamedef.json and returns the new (folderPath, game) to onCreated.
M.openExistingGameDefinition(onOpened)
Opens a native/in-app file picker (file_picker_dialog.lua is what actually renders it) filtered to .json, loads the chosen file with ops.loadGameDefFile, and calls onOpened(folder, game) — or toasts an error if the file isn't a valid game definition.

Editor screen

Editor.new(folderPath, game) builds the four tab objects up front and keeps them alive for the editor's whole lifetime (so switching tabs never re-creates their state):

TabIndexModuleEdits
General1gamedef/settings_tab.luaname, card backs, tag groups
Zones2gamedef/zones_tab.luagame.zones
Sets3gamedef/sets_tab.luagame.sets, adds cards
Cards4gamedef/card_view_tab.luagame.cards

Every tab edits the shared self.game table (owned by the Editor, passed to each tab as editor.game) directly and in place — there is no separate "apply changes" step and, notably, no unsaved-changes prompt on leaving the editor (matching the original Flutter behavior, called out explicitly in the file's header comment). The toolbar (built with widgets.editorToolbar) carries New, Open, a Tools menu and Save; widgets.tabBar renders the four-tab strip below it.

Editor:save() / Editor:write()
save() first checks ops.cardsOutsideSets(game) — cards with no setId are silently dropped by the file format once a game actually uses sets, so this warns (naming up to five affected cards) and requires an explicit "Save Anyway" before calling write(), which calls ops.writeGameDefinition(folderPath, game) and clears the image resolver's cache (in case any image file was replaced during this session).
Editor:openToolsMenu()
Opens a context menu with two entries, both deferring to gamedef/dialogs.lua: "Check for Duplicate Card IDs..." and "Merge Duplicate Card Images...".

gamedef/common.lua — shared helpers

src/ui/screens/gamedef/common.lua
The grab-bag of layout constants and small widgets every tab in this editor is built from.

This file has no screen of its own — it is pure shared infrastructure, required by every other file in gamedef/. The pieces worth knowing about, since they recur constantly across the tab files above and below:

C.keyOf(obj)
Generates (and memoizes, via a weak-keyed table) a stable string id for any Lua table — zones, tag groups, card backs, sets, cards — so widget ids built from keyOf(obj) stay attached to the same logical row across reorders, even though the underlying objects have no natural id field of their own usable as a widget key (and a zone's own id field is itself user-editable text).
C.displayCard(folderPath, card) / C.displayCardBacks(folderPath, cardBacks)
Returns shallow copies with imagePath resolved to a real path via image_resolver.resolveBareImagePath, for drawing only (see the note above on bare vs. resolved paths).
C.chooseImage(destFolder, correctCardOrientation, onResult)
The shared "pick an image file and copy it into the game folder" flow: opens a file picker filtered to ops.imageFilterList, calls ops.copyPickedImage (optionally auto-rotating for a card's declared orientation), invalidates the image cache and resolver for the copied-over path, and calls onResult(fileName) with the bare file name (or nil on cancel/failure, after a toast).

Layout helpers used throughout: C.column(x, w) centers a max-760px-wide content column; C.sectionHeader draws a section title with an optional info tooltip, a count badge and a right-aligned action button; C.groupLabel draws a small primary-colored sub-heading; C.toggleRow/C.toggleGrid lay out labeled on/off switches (one or two columns, depending on available width); C.collapseHeader is the chevron+title+trailing-text row used for every collapsible section; C.stepper is the −/qty/+/remove control used for quantity fields (pack settings, deck entries); C.imagePreviewBox/C.drawImageInBox draw a card-shaped or arbitrary image thumbnail with contain/cover fitting and optional rounding.

gamedef/settings_tab.lua — General tab

src/ui/screens/gamedef/settings_tab.lua
Port of widgets/game_settings_tab.dart: the game's name, its card backs, and its tag groups.

Three sections, top to bottom: the game name field; Card Backs, a drag-reorderable list where the first entry is the game's default back (each row has a clickable thumbnail to choose/clear its image, a name field, and an orientation dropdown — see T:drawCardBackRow); and Tag Groups, a drag-reorderable list of named groups, each expandable to show its tags as removable, drag-to-reorder chips (T:drawTagChips) plus a field to add a new tag.

The chip drag-reorder (T:drawTagChips) is a good example of this app's general "press-and-drag with a threshold" pattern: a press is recorded but doesn't become a drag until the mouse has moved more than 4 logical pixels, at which point an insertion-point indicator (a thin vertical bar) tracks the nearest chip and a release commits the move via widgets.moveItem. The same pattern, generalized to full rows via a widgets.reorder handle object, drives every other drag-reorderable list in this editor (card backs here, tag groups here, zones on the Zones tab).

Tags defined here are the vocabulary used everywhere else: as filter chips in card_filter_bar.lua, as the toggleable chips on each card's form on the Cards tab, and (for any tag group the game nominates as its "Rarity" group) as the keys for a set's pack-generation weights on the Sets tab.

gamedef/zones_tab.lua — Zones tab

src/ui/screens/gamedef/zones_tab.lua
Port of widgets/zones_tab.dart: a reorderable zone list on the left, the selected zone's settings on the right.

A classic list/detail split: T:drawList renders the drag-reorderable zone list (an icon per row — "layers" for a card zone, "widgets" for a widget zone — plus a one-line badge summary from badgesOf(zone), e.g. "Shared · Face up"); T:drawDetail(zone, ...) renders the form for whichever zone is self.selected. "Add Zone" creates a bare ZoneDefinition and selects it immediately.

The detail form always starts with Name, ID, and a Card Zone / Widget Zone segmented toggle (zone.kind), then branches:

T:drawCardZoneFields(zone, k, x, y, w)
Ownership (Shared — one public pile instead of one private pile per player — and, only for owned zones, Visible To All); Behavior (Face Up, Shuffleable, Auto Shuffle, Is Discard Pile); then either Dealing (owned zones: dealsBuiltDeck, with a Deck Type field and an optional-deck toggle shown only while that's on) or Shared Deck (shared zones: a Standard 52-Card Deck toggle, or a Deck Name naming a library deck to auto-load, plus a Left/Right side picker); finally Starting Contents, a list of card+quantity entries — but only shown when no other source (built deck, standard deck, or named deck) already fills the zone, since those take priority (see src/game/session.lua for the precedence this UI is describing).
T:drawWidgetZoneFields(zone, k, x, y, w)
Currently a single widget kind, "Counter": a starting value (typed as text, parsed loosely — any non-numeric input is treated as 0) and starting color / starting text color pickers.

Settings that don't apply to the zone's current configuration are hidden entirely rather than merely disabled (their underlying values are preserved, just not editable) — e.g. Visible To All disappears once Shared is on, and the whole Starting Contents section disappears once a deck source is configured. This keeps the form from ever showing a control whose value has no effect.

gamedef/sets_tab.lua — Sets tab

src/ui/screens/gamedef/sets_tab.lua
Port of widgets/sets_tab.dart: bulk-import a folder of card art as a new set, and configure pack generation.

"Add Set..." is the headline feature: it opens a folder picker, derives the set's id from the folder's own name (ops.deriveIdFromFolderPath), and — after a one-frame delay so a spinner shows first — calls ops.copySetImages to copy every image into <gameFolder>/<id>/ and ops.buildCardsFromImageFolder to synthesize one CardDefinition per image (deriving each card's title from its file name, and guaranteeing unique ids against the game's existing cards). This is the fast path for turning a folder of card scans into a playable set without touching the Cards tab at all.

Each set row shows its name (editable), id and card count, a delete button (T:confirmDelete — removes the set and every card whose setId matches it, after confirmation, since that's destructive to data the Cards tab owns), and — only when at least one card in the set carries a tag from whichever tag group the game uses for rarity — a collapsible Pack Settings section.

packSummary(set) / rarityTags
Pack Settings is a list of (tag, count) pairs — "deal count random cards carrying tag" — consumed by the Pack Generator board widget and by a collection-mode server's pack-opening logic (see src/core/pack_generator.lua). With no settings configured, the collapsed summary reads "10 random cards" (the generator's built-in default), ignoring rarity entirely. ops.rarityTags(game.tagGroups) decides which tag group, if any, counts as the rarity vocabulary offered in the tag dropdown here.

gamedef/card_view_tab.lua — Cards tab

src/ui/screens/gamedef/card_view_tab.lua
Ports widgets/card_view_tab.dart and card_detail_panel.dart: the busiest tab — a filtered pool, a live preview, and a per-card form, in three resizable columns.

Three columns separated by draggable split handles (splitHandle, the same press-and-drag pattern noted on the General tab but constrained to horizontal movement): a filtered card pool grid (T:drawPool, reusing card_filter_bar.lua for the filter/search chips), a live preview of the selected card (T:drawPreview), and its full edit form (T:drawForm). Column widths are tracked as fractions (poolFraction, previewFraction, with the form taking whatever remains) clamped to a 15% minimum each.

T:syncFilters()
Called every frame before drawing: prunes the filter state of any tag-group/tag/set id that no longer exists in the game (since those are freely edited on other tabs, a filter can reference something that just got deleted or renamed) and resets the sort key if it referenced a group that's gone.
T:tabToCard(delta) / T:keypressed(key)
Pressing Tab with no field focused moves the selection to the next/previous card in the current filtered view (Shift+Tab goes backward). Two checkboxes under the preview — "Tab navigates inside form fields" and "Tab focuses and selects Card Title" — change what Tab does while a field in the form has focus, letting a user who is rapidly re-titling many cards tab straight from one title field to the next card's title field with its text pre-selected, without touching the mouse.

The preview pane (T:drawPreview/drawFrontPane/drawBackPane) shows the card's actual image at its native aspect ratio (unlike the cropped pool tiles), and — for a card with a cardBackId set — both Front and Back side by side, with Previous/Next navigation and a position counter ("i / N") against the current filtered list.

The form (T:drawForm) edits, in order: title and delete; orientation and set (side by side); image (file name display, Choose/Clear — routed through common.chooseImage, with orientation-aware auto-rotation); card back (a dropdown of the game's named backs, a Default option, or "Unique" to pick this card's own back orientation independent of any named back); one collapsible chip section per non-empty tag group (click a chip to toggle that tag on card.types); an Extra Fields editor (free-form key/value pairs, stored as a JSON object on card.extraFields — see T:extraRows/writeExtraFields, which round-trip through the ordered-key metadata lib/json.lua attaches to decoded objects so field order in the saved file matches what the user typed); and finally two toggles, Unownable (the card always stays unowned on the table, so any player can interact with it — used for communal resources) and Free Card (on a collection-mode server, every player always has unlimited copies of it regardless of what they've unlocked).

gamedef/dialogs.lua — Tools-menu dialogs

src/ui/screens/gamedef/dialogs.lua
Ports duplicate_card_ids_dialog.dart and duplicate_card_images_dialog.dart — the two entries under the editor toolbar's Tools button.
D.showDuplicateCardIds(editor)
Finds every group of cards sharing the same id (ops.duplicateIdGroups) and shows one editable ID field per affected card (grouped under its colliding id, with the card's title and set name for context), so the user can manually re-key each one to something unique. The groups are computed once when the dialog opens, so a row doesn't disappear mid-edit the instant its id becomes unique — Save applies every pending id change at once and calls models.GameDefinition.invalidateIndex(game) (see src/core/models.lua) to rebuild the id-based lookup index.
D.showMergeDuplicateImages(editor)
Finds groups of cards that share both a set and an image file (ops.duplicateImageGroups) — a common artifact of re-importing art — and offers to merge each group into its first card, unioning their tags (ops.unionTypes) and deleting the rest (ops.mergeDuplicateImageCards). The preview lists, per group, the surviving card's title/set, how many cards will be merged into it, and the union of tags it will end up with, before the user commits.

Both dialogs are read-only analyses until their action button is pressed — opening the Tools menu never mutates game.cards by itself, and a group with nothing to merge/rename (an empty result) short- circuits straight to a toast ("No duplicate card IDs found." / "No duplicate card images found.") instead of opening an empty dialog.
