Save-directory layout

CardTable keeps two different kinds of state on disk, and src/data/paths.lua is the single place that knows where each one lives:

  • LÖVE's sandboxed save directory (love.filesystem.getSaveDirectory(), identity "cardtable" from conf.lua) — this is where settings.json, the player's avatar and (when running with --identity) a second, isolated profile live. It is created lazily by LÖVE, so paths.supportDir() calls fs.mkdirs on it before anyone writes into it by absolute path. paths.migrateLegacyIdentity(oldIdentity) is a one-time carry-over from the app's previous identity ("cardflux", from before the CardTable rename): if the current identity's folder has no settings.json yet but a sibling folder named for oldIdentity exists, it copies that folder's contents in. main.lua calls it once at startup, before src/app.lua loads, and only when --identity wasn't overridden.
  • User-chosen library folders — the game library (game_library/ next to the executable by default) and the deck library (deck_library/) are plain folders on the real filesystem, outside LÖVE's sandbox, because the user needs to drop in game definitions and share decks with a file browser. Their locations are overridable and remembered in settings.json via paths.setGamesDir / paths.setDecksDir.

Everything under src/data/ builds on these two roots, reading and writing through fs.lua rather than Lua's stock io/os libraries, because library folders need real absolute-path access (non-ASCII paths included) that love.filesystem — sandboxed to the save directory and the fused executable — cannot provide.

paths.lua — well-known locations

src/data/paths.lua
Port of lib/data/app_directory.dart. Computes every directory the app cares about.
P.appDir()

Folder holding the executable in a fused (packaged) build, or the project source folder when running love . in development. Used as the base for the default library folders and as the installDir the self-updater mirrors files into.

P.supportDir()

LÖVE's per-user save directory, created on first call if it doesn't exist yet. The Flutter-app analog of an application-support directory.

P.defaultGamesDir() / P.defaultDecksDir()

appDir()/game_library and appDir()/deck_library.

P.gamesDir() / P.setGamesDir(path) / P.decksDir() / P.setDecksDir(path)

The effective library folders: a user override from settings.json (settings.keys.gamesDirectoryPath / decksDirectoryPath) when it is an absolute path, otherwise the default. setGamesDir/setDecksDir assert the path is absolute — a defensive check against a historical file-dialog bug that could save a bare folder name.

P.avatarDir()

supportDir()/avatar — where profile.lua stores the resized player avatar PNG.

See also platform.html — the self-updater, which calls paths.appDir() as its install directory and excludes paths.gamesDir()/paths.decksDir() from being overwritten when they live inside it.

fs.lua — absolute-path filesystem access

src/data/fs.lua
Cross-platform file/directory operations outside LÖVE's sandbox, built on LuaJIT FFI.

LÖVE's own love.filesystem API can only see inside its sandboxed save directory and the fused executable's bundled assets, so any access to the game/deck library folders (which can be anywhere the user points them) has to go around it. fs.lua provides that access, with two back ends selected once at load time by ffi.os:

  • Windows — directory listing, creation, deletion, moves and attribute checks go straight to the wide-char (UTF-16) Win32 API (FindFirstFileW/FindNextFileW, CreateDirectoryW, MoveFileExW, …) via ffi.cdef, because Lua's own io library uses the process's ANSI codepage and mangles non-ASCII paths. File contents similarly go through _wfopen/fread/fwrite from msvcrt (the wideIO table) instead of io.open, for the same reason.
  • Non-Windows (secondary targets) — falls back to POSIX opendir/mkdir/ rename via FFI, and shells out to ls -1Ap for directory listing because struct dirent's layout isn't portable across libc implementations.
fs.join(...), fs.basename(p), fs.dirname(p), fs.extension(p), fs.stripExtension(name)

Pure string path helpers; accept both / and \ on Windows and normalize to the platform separator (fs.sep).

fs.readFile(path) / fs.writeFile(path, data)

Whole-file binary I/O, routed through the wide-char CRT on Windows once it's installed.

fs.exists(p) / fs.isDir(p) / fs.isFile(p)

Existence/type checks built on the platform's raw attrs lookup.

fs.list(dir)

Returns { {name, isDir, size, mtime}, ... } sorted case-insensitively by name, or nil if dir isn't a readable directory. mtime on Windows is converted from a Win32 FILETIME (100ns ticks since 1601) to Unix seconds.

fs.mkdirs(p) / fs.remove(p) / fs.removeTree(p) / fs.move(a, b) / fs.copy(a, b) / fs.copyTree(from, to)

Recursive directory creation/deletion/copy built from the primitives above — these are the workhorses almost every other src/data module calls.

fs.exePath() / fs.tempDir()

The running executable's path and the OS temp folder; used by the updater (staging a download) and the JPEG-rotation helper (a scratch PowerShell script).

settings.lua — key/value store

src/data/settings.lua
Persistent settings, replacing Flutter's shared_preferences. Backing file: settings.json in LÖVE's save directory.

S.keys is the single table of setting names every other module references (never a raw string), deliberately kept identical to the original Flutter app's preference keys (games_directory_path, player_profile_name, dark_mode_enabled, …) plus a few LÖVE-port-only additions (ui_scale, recent_servers, selection_color).

S.get(key, default) / S.set(key, value) / S.remove(key)

The whole file is lazily loaded into an in-memory table on first access (load()) and rewritten in full, key-sorted, on every set/remove (save()) — there's no incremental-write path, which is fine at this file's size. Encoding/decoding goes through lib/json.lua.

Consumers: paths.lua (library folders), profile.lua (player identity, Discord token, dark mode), hand_settings.lua / table_settings.lua, and src/app.lua for the UI-scale setting.

profile.lua — player profile, reconnect & avatar

src/data/profile.lua
Ports player_profile_settings.dart, player_avatar_file_ops.dart, avatar_image_utils.dart, reconnect_settings.dart, discord_auth_settings.dart and theme_mode_settings.dart into one module.
P.getName/setName, P.getColor/setColor, P.getAvatarPath/setAvatarPath

The identity shown to other players — read by src/app.lua's App.loadProfile() into App.profile at startup.

P.getReconnectPlayerIdFor(hostKey) / P.saveReconnect(hostKey, playerId)

Remembers only the most recent host and the player id it assigned, so a dropped connection to that same host can silently rejoin as the same seat (see net.html for the reconnect handshake).

P.getRecentServers() / P.addRecentServer(host, port) / P.removeRecentServer(host, port)

A capped (5-entry), most-recent-first list shown by the multiplayer Join screen.

P.getDiscordRefreshToken / saveDiscordRefreshToken / clearDiscordRefreshToken

Persists the OAuth refresh token so discord.lua's invite flow doesn't need the consent screen on every launch.

P.getDarkMode() / P.setDarkMode(v)

Read once at startup by src/app.lua and written whenever the title bar's theme toggle is clicked.

P.saveAvatar(sourcePath, dir) / P.deleteAvatar(dir) / P.readAvatarBytes() / P.resizeAvatarBytes(bytes)

Avatar handling: a picked image is decoded, downscaled so its longer side is at most P.avatarMaxDimension (256px) via image_utils.lua, re-encoded as PNG and written to <supportDir>/avatar/avatar.png (any existing avatar.* file is cleared first, in case the stored extension ever changes).

hand_settings.lua & table_settings.lua — display preferences

src/data/hand_settings.lua
LÖVE-port-only. Layout of the player's fanned hand (see CONTROLS.md's "Settings > Hand"): card size, spacing, tilt, max fan spread, resting height above the hand area, and how much of a hovered card is revealed.

H.defs is an ordered list of slider definitions (id, label, min, max, step, default, format) that the Settings dialog iterates directly to build its UI — adding a new hand slider means adding one entry here. Each value is stored under settings.json key "hand_<id>", but only when it differs from the default (H.set calls settings.remove when a value is reset to default, keeping the file minimal). H.set(id, v, live)'s live flag updates only the in-memory cache while a slider is being dragged, deferring the disk write (and the associated full-file JSON re-encode) until the drag ends.

src/data/table_settings.lua
LÖVE-port-only. The single "Settings > Table" preference: the box-selection tint color, stored as an ARGB integer under selection_color.

Both modules follow the same cache-plus-default-omission pattern as each other and are read every frame by src/ui/table/* while drawing hands and selection highlights, so the in-memory cache (rather than re-parsing settings.json) matters for performance.

save_files.lua — save games & game logs

src/data/save_files.lua
Ports save_game_file_ops.dart and game_log_file_ops.dart. Saves live in <gameFolder>/savegames/<name>.json, logs in <gameFolder>/gamelogs/<fileName> — inside the game's own library folder, not the LÖVE save directory, so saves travel with the game and are easy for a player to find.
S.writeSaveGame(gameFolderPath, name, save) / S.readSaveGame(filePath)

Serializes/deserializes a SavedGame (see core.html — models.lua) to/from JSON.

S.listSaveGames(gameFolderPath)

Newest-first listing for the Load Saved Game screen; unreadable or foreign JSON files are silently skipped. Sort order is computed from each save's ISO-8601 savedAt timestamp via a zero-padded, lexicographically-sortable key (sortKey).

S.logFileName(nowSeconds) / S.formatLog(entries) / S.writeLog(gameFolderPath, fileName, contents)

Backs the in-game "Save Log" button: a timestamped file name, "[mm:ss] message" formatted lines, and the write itself.

game_loader.lua — loading a game library

src/data/game_loader.lua
Port of game_loader.dart. Turns a folder full of gamedef.json files into ready-to-play GameDefinitions with resolved image paths.
L.loadFromFolder(folderPath)

Loads every gamedef.json (case-insensitive) directly inside one folder, resolving each card/back's bare image file name to an absolute path via image_resolver.lua and appending the generated 52-card deck when any zone requests standardDeck. Returns games, errors — a bad file is skipped and recorded rather than aborting the whole load.

L.loadGamesFromDirectory(rootPath) / L.loadLibrary(rootPath)

Walks every direct subfolder of the library root (one game per subfolder) and appends the bundled "Standard 52-Card Deck" (L.loadStandardDeck(), read from the fused app's own assets/games/standard_52/standard_52.json) last — this is what the game picker actually calls.

L.withStandardDeckCards(game)

Appends the 52 generated playing-card definitions (from models.buildStandardDeckCards()) to any game that has a zone flagged standardDeck, without duplicating ids already present.

Note the split in responsibility from gamedef_ops.lua below: game_loader.lua resolves image paths for playing a game, while gamedef_ops.lua deliberately loads the same files unresolved (bare file names) for editing one, so a save round-trips without rewriting paths.

gamedef_ops.lua — game-definition editor file helpers

src/data/gamedef_ops.lua
Ports game_definition_file_ops.dart and library_folder_migration.dart. All the file-level operations behind the Game Definition Editor.
O.writeGameDefinition(folderPath, game) / O.loadGameDefFile(jsonPath, folderPath) / O.scanGameLibrary(root)

Write/read a single gamedef.json (2-space indent) and enumerate every editable game under a root folder, sorted by name. loadGameDefFile intentionally skips image-path resolution — the editor keeps and re-saves bare file names.

O.createGameDefinition(root, id) / O.validateGameId(id)

Creates a new game's stub folder + gamedef.json; validateGameId rejects anything that can't be a filesystem folder name (/\\:*?"<>|, ., .., empty).

O.copyIntoFolder / O.copyPickedImage / O.copySetImages

Copies art the user picks (single file or a whole folder) into the game's folder, optionally rotating landscape images to portrait via image_utils.lua's rotateLandscapeImages (batched so a folder of JPEGs needs only one PowerShell helper invocation, not one per file).

O.buildCardsFromImageFolder(sourceFolderPath, setId, existingCardIds)

Bulk-imports a folder of card art as one CardDefinition per image (sorted by file name), skipping any file that is itself a card-back image (suffix models.cardBackFileSuffix), and de-duplicating ids against what's already in the game via O.uniqueCardId (appends _001, _002, …).

O.duplicateIdGroups(cards) / O.duplicateImageGroups(cards) / O.mergeDuplicateImageCards(cards)

Powers the editor's duplicate-id and duplicate-image warning dialogs. Two cards are an "image duplicate" when they share both setId and exact imagePath (keyed as setId .. "\0" .. imagePath — a NUL byte can't appear in either half, so the two can't collide across the boundary); merging unions their types and keeps only the first card.

O.cardsOutsideSets(game) / O.rarityTags(tagGroups)

cardsOutsideSets flags cards that a save would silently drop (once a game declares sets, gamedef.json stores cards only nested inside their set). rarityTags finds the tag group named "Rarity" (case-insensitive) — the tag vocabulary the Pack Generator's rarity weighting UI offers.

O.directoryHasEntries(path) / O.moveDirectoryContents(fromPath, toPath)

Supports the one-time migration prompt when a user's previously-configured library folder needs moving.

deck_library.lua — scanning deck files

src/data/deck_library.lua
Port of deck_library_loader.dart. Finds and validates .json deck files on disk; a deck's display name is simply its file name minus the extension.
D.loadDecksForGame(rootPath, game) / D.loadBuiltInDecksForGame(game) / D.loadAllDecksForGame(rootPath, game)

Scans the player's own deck-library subfolder for a game (<rootPath>/<gameId>) and/or the game's bundled decks/ folder, returning { entries = {...}, incompatible = {...} }. incompatible catches decks saved in a legacy format (detected via a legacyDeckFormat flag raised by DeckConfig.fromJson) that parse as JSON but not as a valid deck — surfaced to the user rather than silently dropped. loadAllDecksForGame lists the player's own decks before the game's built-ins.

D.readDeckFile(path)

Reads one arbitrary deck file (the "Browse for file..." picker option), returning deck or nil, reason where reason is "legacy", "invalid" or "unreadable".

D.validateName(name, emptyMessage) / D.writeDeck(rootPath, gameId, name, deck)

Name validation mirrors O.validateGameId's forbidden-character rule; writeDeck writes compact (no indent) JSON, matching the original Flutter app's deck file format byte-for-byte where it matters for compatibility.

deck_store.lua — local vs. server deck storage

src/data/deck_store.lua
A small abstraction so the deck-management UI doesn't need to know whether it's talking to the local deck-library folder or a CardTable server account.

Where deck_library.lua is the low-level file scanner, deck_store.lua wraps it (plus server_client.lua) behind one shared interface — store.kind ("local" or "server"), store.label, and three async methods:

store:list(game, cb) -> cb({ entries, incompatible }, err)
store:write(game, name, deck, cb) -> cb(ok, errMessage, where)
store:remove(game, name, cb) -> cb(ok, errMessage)

M.localStore() implements these synchronously (wrapped in a callback for interface symmetry) against paths.decksDir(). M.serverStore(sc) implements them as requests over a server_client connection (deckList, deckSave, deckDelete — see net.html) and merges in the game's built-in decks (which ship inside the locally cached game folder, not on the server) alongside the server's results. Its optional alsoLocal flag makes every server save also write a local copy, surfacing a distinct warning if only the local copy fails.

The image pipeline

Card art can run into the hundreds of multi-megabyte files per game, so CardTable never decodes or loads images synchronously on the main thread. Four modules split the job:

ModuleRole
image_resolver.luaTurns a card/zone's logical reference (a bare file name, a card-back id, "the game's logo") into a concrete, existence-checked absolute path.
image_utils.luaPure decode/encode/pixel operations (PNG/JPEG/BMP/TGA/GIF via LÖVE, WebP via an optional libwebp FFI binding) that work with no window — usable from worker threads and tests.
image_cache.luaMain-thread-facing cache: get(path) returns a usable Image or nil while it loads; owns a small pool of worker threads and a VRAM eviction budget.
image_worker.luaThe worker thread body: pulls decode requests off a channel, decodes+downscales off the main thread, and pushes results back.

The cache's lifecycle, driven once per frame from src/app.lua's App.update (imageCache.update()):

  1. A screen calls imageCache.get(path). On a cache miss this lazily starts the worker pool (ensureWorkers, sized to processorCount - 1, capped at 4) and pushes a {key, path, maxDim} request onto the shared requests channel, immediately returning nil (the entry is marked "loading").
  2. A worker thread (running image_worker.lua) pulls the request, decodes the file via image_utils.decodeFile, downscales it to fit maxDim (1024px by default), and pushes the key followed by the decoded ImageData (or an error string) back atomically on the results channel — performAtomic keeps the key/payload pair from interleaving with another worker's push.
  3. On the main thread, C.update() pops up to maxUploadsPerFrame (8) results per frame, uploads each to the GPU as a mip-mapped Image (makeImage), and flips the entry to "ready" (or "error").
  4. evict() then checks the running VRAM estimate (usedBytes, computed from each image's dimensions assuming RGBA8 plus mip chain) against budgetBytes (768 MB); if over budget, the least-recently-used ready entries (by the frame they were last fetched with get) are released first, down to 80% of budget.
C.get(path) / C.status(path) / C.errorFor(path)

The public read path: a screen's draw code calls get every frame and checks status ("ready" | "loading" | "error" | nil) to decide whether to draw the image, a placeholder, or an error glyph.

C.putBytes(key, bytes)

Synchronous path for in-memory image bytes that didn't come from disk (e.g. an avatar downloaded from a server) — decodes and uploads immediately rather than round-tripping through a worker.

C.invalidate(key) / C.clear() / C.shutdown()

invalidate forces a reload on the next get (used after the gamedef editor changes a file on disk). shutdown pushes a "quit" message to each worker and joins them — called from App.quit().

image_resolver.lua

src/data/image_resolver.lua
Port of image_path_resolver.dart. Resolves logical image references to absolute, existence-checked paths, memoizing the filesystem checks.
R.resolveBareImagePath(folderPath, bareImagePath, setId)

A card's bare file name lives under folderPath directly, or folderPath/setId when the card belongs to a set — this is the one join every other resolver function builds on.

R.resolveCardBackImagePath(cardBacks, card)

Returns path, missing, orientation for the back a card should show: a per-card "unique back" (derived from the card's own art via uniqueCardBackPathFor, which inserts the back-file suffix before the extension) when flagged, otherwise the card's chosen (or the first) game-wide card back.

R.resolvePackGeneratorImagePath / R.resolveGameLogoImagePath / R.resolveImageAnyExt

Probes a folder for a specific base name across every known extension in turn (resolveImageAnyExt) — used for the Pack Generator widget's icon and a game's optional logo.

R.mergeLocalImagePaths(remote, localGame)

When joining a multiplayer game, the host's GameDefinition arrives over the network with no meaningful image paths for this machine; this rebuilds it using this client's local copy's image paths (falling back to no image for any card the local copy lacks) and local card backs/folder. See net.html and game.html for how the synced definition is used.

Existence checks (fs.isFile) are memoized in existsCache since they run during drawing; call R.clearCache() after any on-disk change (an editor save, a manual refresh).

image_utils.lua

src/data/image_utils.lua
Headless decode/encode/pixel-manipulation helpers, usable from worker threads (and tests) because they touch no window state.
I.decodeBytes(bytes, name) / I.decodeFile(path)

LÖVE's love.image.newImageData handles PNG/JPEG/BMP/TGA/GIF natively. WebP (detected by its RIFF....WEBP magic bytes) is decoded through libwebp.dll/.so if present next to the executable or on the library path — loaded lazily and best-effort via FFI (loadWebp), including a search for a co-located libsharpyuv dependency so Windows can resolve the import even though the app folder isn't normally on the DLL search path. Without the DLL, WebP images simply fail to decode with a clear error.

I.rotateClockwise(src) / I.downscaleToFit(src, maxDim)

Pixel-level operations on RGBA8 ImageData accessed directly via getFFIPointer() for speed: a 90° clockwise transpose, and an area-average downscale (not a cheap nearest-neighbor resize) so shrinking card art doesn't look aliased.

I.rotateLandscapeImages(paths)

Used by the gamedef editor when importing art: PNGs are rotated in-process (decode, rotate, re-encode); JPEGs — which LÖVE can't encode — are batched into one PowerShell/System.Drawing helper script (I.rotateJpegsWindows) so a folder import needs a single external process rather than one per file. Best-effort: a failure just leaves that file as originally copied.

image_cache.lua & image_worker.lua

Covered in detail above under The image pipeline. In short: image_cache.lua is the main-thread cache/scheduler; image_worker.lua is the small, stateless loop run inside each worker thread it spawns (requests:demand() → decode+downscale → push the result pair → repeat until a "quit" message arrives).
